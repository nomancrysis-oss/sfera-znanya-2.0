СФЕРА ЗНАНИЙ — РОЛЬ АДМИНИСТРАТОРА

1. СОХРАНИТЕ КОПИЮ текущего сайта и экспорт базы Supabase до обновления.
2. В Supabase > SQL Editor > New query вставьте и выполните весь файл supabase-admin-upgrade.sql. Исходный supabase-setup.sql повторно НЕ запускать.
3. В Supabase > Authentication > Users создайте постоянную учётную запись администратора с email и надёжным паролем (Add user). Подтвердите email при необходимости. Используйте отдельный пароль, включите MFA, если доступна.
4. Скопируйте User UID именно этой email-учётной записи из Authentication > Users.
5. В SQL Editor выполните, заменив UUID на реальный User UID:
   INSERT INTO public.site_admins(user_id) VALUES ('ВАШ-UUID') ON CONFLICT (user_id) DO NOTHING;
   Пароль в SQL, HTML, GitHub и в чате НЕ указывать.
6. Перенесите действующие url и anonKey (только publishable key!) из своего текущего supabase-config.js в файл новой версии. В архиве настройки намеренно пустые.
7. Обновите файлы сайта в GitHub; Vercel выполнит публикацию. Если сайт настроен на другую корневую папку, сохраняйте ту же структуру.
8. На сайте откройте «Настройки и помощь» > «Войти как администратор», введите email/пароль. После входа откройте облачную карточку другого автора: кнопка «Удалить» станет доступной. Для остальных пользователей удаление ограничено собственными карточками.
9. Проверьте в отдельном браузере: обычный посетитель НЕ может удалить чужую карточку; администратор может. После удаления запись исчезает из public.lessons.

БЕЗОПАСНОСТЬ:
- Администратор определяется на сервере по RLS-функции public.is_site_admin(); скрытая кнопка не является механизмом защиты.
- Не публикуйте пароли, секретные ключи и UUID с доступом к служебным аккаунтам.
- Роль администратора разрешает удаление чужих карточек, но НЕ редактирование чужих.
- Встроенные исходные карточки (source-...) находятся в index.html, а не в базе, поэтому удалять их через Supabase нельзя.
- Обычные посетители по-прежнему используют анонимные сессии. Для публичного сайта рекомендуется CAPTCHA, лимиты и модерация.
- Удаление из Supabase необратимо без резервной копии.
- Тестирование с действующим Supabase не проводилось: нет доступа к вашему проекту.
